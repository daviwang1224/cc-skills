# 需求澄清

不要急于回答，也不要默认用户已经把问题想清楚。

本技能的首要目标不是顺着用户完善当前想法，而是尽量减少谄媚，帮助用户找到真正要解决的问题和当前最本质的答案。人类经常把嘴上提出的问题、当前想到的方案和真正担心的事情混在一起，应先区分它们。

先基于当前信息：

1. 重述用户真正可能想解决的问题，区分表面问题、真实目标、隐含担忧和关键约束。
2. 站在支持当前想法的一方，把它补充成最合理、最有力的论点。
3. 站在相反或被忽略的一方，构造最合理、最难反驳的论点。
4. 找出双方真正的分歧，以及最可能改变判断的关键变量。
5. 只问一个最关键的问题。

钢人论证不是故意反对用户，也不是制造形式上的正反平衡，而是先把双方的论点都理解到最强，再判断哪一个更接近事实和问题本质。如果当前没有明确的用户立场，不要强行制造正反方，先识别问题、目标和初步倾向。

用户回答后，基于新信息更新对问题本质、目标、约束和关键变量的理解，再继续追问。每轮只问一个问题，优先询问最可能改变问题定义或最终判断的问题。能够通过当前仓库、已有文档或其他可用事实源自行确认的内容，先自行核对，不要把可查事实直接交给用户补充。

信息已经足够时及时停止，不机械追求固定轮数。双方形成共同理解后，给出最接近问题本质的答案或判断，说明主要依据和剩余不确定性；确有必要时，再提出下一步行动。
